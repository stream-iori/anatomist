# 单进程 Semantic Pipeline：F0–F7 实施计划

## 总结

新增单进程融合入口，同时保留现有 Shell 管道：

# 日常使用

anatomist pipeline --index index.db -- \
 resolve 'p.Service#run()' --kind callable --exact --unique \
 --then calls \
 --then dispatch

# 自动化

anatomist pipeline --index index.db --file pipeline.json

公共语法规则：

- --file 与内联 -- ... --then ... 互斥。
- pipeline.json 保持现有格式：{"stages":[["resolve",...],
["calls"]]}。

- 只接受白名单命令，不执行 Shell、不支持重定向或外部程序。
- 限制为 1–16 个 stage、每 stage 最多 256 个 argv、JSON 文件最大 1
  MiB。

- stage 内禁止 --index/--module/--scope/--format；这些只能由
  pipeline 全局指定。

- stage 内禁止 --help/--version；帮助统一通过 anatomist pipeline
  --help。

- --then 是内联语法保留字。
- search --count、overview、source 等无法继续组合的输出只能作为末
  段；其余组合根据解析后的实际输入/输出 record 类型预检。

- 首段可以是 producer，也可以从 stdin 接收已有 semantic stream。
- 发生错误时 stdout 可能已有流式结果，但不会出现最终 stream
  evidence。

错误格式：

{"code":"PIPELINE_STAGE_FAILED","stage":2,"command":"calls","cause_ex
it":2,"cause_code":"INPUT_TYPE_MISMATCH","message":"..."}

统一使用 exit 5，错误码包括：

- PIPELINE_INVALID_SPEC
- PIPELINE_INCOMPATIBLE_STAGES
- PIPELINE_STAGE_FAILED
- PIPELINE_LIMIT_EXCEEDED

stage 从 1 开始；不得输出堆栈或多行 stderr。

完成门禁 产品回归 PASS；30 次同 binary 自检 PASS；工作区只允许保

───────────────────────────────────────────────────────────────────
阶段 F1 共享上下文
实施内容 新增 SemanticExecutionContext，统一持有 QueryService、
SemanticIdentity、capability registry、module/scope 和只
读 SQLite snapshot。单命令仍自行创建并关闭 context；
pipeline 只创建一次。将错误捕获与实际查询执行分离。
完成门禁 所有现有单命令测试输出、退出码不变；连接生命周期测试证明
pipeline 只打开一次。
───────────────────────────────────────────────────────────────────
阶段 F2 统一 Stage 协议
实施内容 定义 SemanticStage、StageDescriptor、StageSession、
SemanticSink。Descriptor 在参数解析后给出输入类型、输出
类型及 producer/transformer/terminal 属性。迁移 17 个
SemanticCommand，并把 search、declarations-of、overview
三个 producer 接入相同协议；业务查询继续复用现有
QueryService。
完成门禁 20 个命令均可通过 standalone adapter 执行；原 CLI stdout
字节不变。
───────────────────────────────────────────────────────────────────
阶段 F3 CLI 与规格解析
实施内容 注册懒加载 pipeline 命令；实现 --then 分段和 --file JSON
解析；使用现有 Picocli command class 解析每段参数；执行
前完成命令白名单、公共参数、stage 数和 record 类型兼容检
查。
完成门禁 CLI contract 测试覆盖双入口、互斥参数、空 stage、未知命
令、写命令、非法组合和上限。
───────────────────────────────────────────────────────────────────
阶段 F4 Spool 参考执行器
实施内容 先实现单进程、单连接、临时 NDJSON 文件串联的参考执行器，
用于验证生命周期、参数和输出等价；所有成功/失败路径自动
清理临时文件。该实现不暴露 transport 开关。
完成门禁 现有 Shell 与 spool 在正向场景 stdout 原始字节一致；失败
场景返回新的 pipeline JSON 错误。
───────────────────────────────────────────────────────────────────
阶段 F5 完整正确性门禁
实施内容 扩展 Golden runner：每个 pipeline.json 同时执行 Shell 和
fused；成功场景先原始字节对拍，再与 expected 对拍。为
fused 错误建立独立 expected stderr/exit。补充 native
smoke、stdin 首段、unsupported capability、空结果、歧
义、limit、Broken Pipe、索引替换和临时文件清理测试。
完成门禁 Maven 全量、19 个 Golden、JVM/native、extension E2E 全部
通过。
───────────────────────────────────────────────────────────────────
阶段 F6 Spool 性能检查点
实施内容 扩展专项 benchmark runner：baseline 使用 f5a9ef2 Shell
pipeline，candidate 使用 fused CLI；两者读取同一个只读
DB，5 次预热、30 次 ABBA 交替采样。记录 stage 数、
binary/DB SHA、p50/p95、RSS 和输出等价。
完成门禁 输出完全一致；单段 p50 ≤ +15%、p95 ≤ +25%；记录 spool
calls 改善值，但无论结果如何继续 F7。
───────────────────────────────────────────────────────────────────
阶段 F7 Typed 有界执行
实施内容 删除 spool transport。抽出可同时服务 NDJSON reader 和内
存 sink 的 SemanticFrameAssembler；中间只传
SemanticRecord/SeedFrame。每个 stage 一次处理一个输入
frame，先完成自己的数据库 cursor，再向下游排放该 frame
的输出，避免共享连接上的嵌套 ResultSet。中间 stream
evidence 被消费，只有末段写 stdout。保持 LinkedHashMap
字段顺序和现有 seed/evidence 生成规则。
完成门禁 全量正确性门禁再次通过；两个 calls workload p50 均至少改
善 25%；所有 workload p95 不回归超过 25%；查询前后 DB
SHA 不变；无 spool 文件和第二套 transport 残留。

## Typed 数据流

CLI/JSON spec
│
▼
StageDescriptor 预检
│
▼
一个只读 SQLite snapshot
│
▼
Producer Session
│ Map records
▼
SemanticFrameAssembler
│ SeedFrame（有界）
▼
Transformer Session ──► ... ──► Final SemanticStreamWriter

具体约束：

- 每条 stage 边只保留当前输入 frame 及其输出 frames。
- 沿用现有上限：100,000 records/seed、100,000 seeds、1,000,000
  records/stream。

- stage 处理期间产生的输出先暂存在当前 frame 缓冲；数据库 cursor 关
  闭后再交给下游。

- pipeline 开始时建立只读 snapshot，整个执行期间 identity 不变化。
- typed record 仍保留原始 LinkedHashMap，最终 Writer 因而能产生字节
  一致的 NDJSON。

- 单命令继续走 NDJSON stdin/stdout adapter，不改变 semantic-stream/
  v1。

## 假设

- pipeline 是 1.0 的新增稳定命令，不标 experimental。
- 原 Shell 管道继续支持，但不会自动融合。
- 不加入 daemon、Shell builtin、自定义 Shell 解释器或任意命令执行。
- 不修改 SQLite schema、semantic-stream/v1 wire contract 或查询业务
  语义。

- 不执行 git push，不提交用户的 todo/annotate-docs.md。
