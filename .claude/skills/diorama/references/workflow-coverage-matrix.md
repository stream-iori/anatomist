# Coverage Matrix: 8 维度覆盖分析

## 职责

Coverage Matrix 输出当前 task 在 Diorama 定义的 8 个测试覆盖维度上的覆盖情况。

它应：
- 从 `design.md` 中提取已覆盖的维度
- 对照 8 维度列表标注覆盖/未覆盖
- 为 plan/generate 阶段提供覆盖盲区提醒

它不应：
- 替代 plan 阶段的业务分析
- 自动添加缺失的场景
- 决定最终测试范围（由人确认）

## 触发方式

```text
/diorama coverage-matrix
```

## 8 覆盖维度

| # | 维度 | 说明 | 典型覆盖来源 |
|---|------|------|-------------|
| 1 | 主流程正确性 | Happy path 验证 | design.md §5 场景规格中的主场景 |
| 2 | 业务规则正确性 | 校验规则、状态机转换 | design.md §5 中的边界场景 |
| 3 | 依赖失败与恢复 | 外部超时、5xx、降级 | design.md §6 中的 Stub/Mock 策略 |
| 4 | 数据一致性 | DB/Cache/MQ 一致性 | design.md §6 中的 SUT 边界 |
| 5 | 鲁棒性与边界 | 幂等、并发、边界值 | design.md §5 + rules/index.md |
| 6 | 完成语义与时序 | 同步/异步/最终一致 | design.md §5 中的 completion 语义 |
| 7 | 可观测性与合规 | 审计日志、事件发布 | design.md §8 验收标准中的 observe 约束 |
| 8 | 兼容性与扩展 | API 版本兼容、批处理 | design.md §6 中的变更清单 |

## 数据提取规则

### 从 design.md 提取

- §5 场景规格中的每个场景对应维度 1（主流程）
- 包含边界/异常描述的场景对应维度 2（业务规则）和 5（鲁棒性）
- 包含外部依赖交互的场景对应维度 3（依赖失败）
- 包含异步/最终一致描述的场景对应维度 6（完成语义）
- §6 实现上下文的 Stub/Mock 策略 → 维度 3
- §6 实现上下文的 SUT 边界 → 维度 4
- §8 验收标准的验证矩阵 → 所有维度的显式标注
- §6 实现上下文的变更清单 → 维度 8

### 从 rules/index.md 提取

- 读取 index.md 中指向的规则文件
- 覆盖维度要求 → 辅助判断维度 5/7 是否满足项目标准

## 输出格式

```markdown
# Coverage Matrix: [task name]

| # | 维度 | 覆盖 | 来源 | 备注 |
|---|------|------|------|------|
| 1 | 主流程正确性 | ✅ | Scene 1, Scene 2 |  |
| 2 | 业务规则正确性 | ✅ | Scene 3 |  |
| 3 | 依赖失败与恢复 | ❌ | — | PRD 中未覆盖外部超时场景 |
| 4 | 数据一致性 | ⚠️ | PRD §6 SUT 边界 | 部分覆盖，缺少缓存一致性 |
| 5 | 鲁棒性与边界 | ❌ | — | 需补充幂等性测试 |
| 6 | 完成语义与时序 | ✅ | Scene 2 | 异步回调已覆盖 |
| 7 | 可观测性与合规 | ⚠️ | PRD §8 验收标准 | 审计日志需确认 |
| 8 | 兼容性与扩展 | ❌ | — | 非本次 task 范围 |

## 覆盖统计

- ✅ 已覆盖: 3
- ⚠️ 部分覆盖: 2
- ❌ 未覆盖: 3
- 覆盖率: 50% (含部分覆盖)
```

## 标注规则

- `✅`：至少有一个场景/评估条目明确覆盖
- `⚠️`：有相关提及但不完整
- `❌`：无任何覆盖来源

## 与 plan/generate 的关系

- coverage-matrix 是**只读分析**，不修改任何文件
- plan 阶段可参考覆盖矩阵调整 tasks.md
- generate 阶段可参考矩阵确保测试代码覆盖已标注维度
- coverage-matrix 不构成 phase protocol 的强制步骤
- plan phase-exit 前建议自动执行 coverage-matrix，输出覆盖盲区提醒，帮助用户在进入 generate 之前发现 specify 遗漏的维度
